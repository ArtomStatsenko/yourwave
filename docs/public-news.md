# Экспериментальные новости Reddit и Telegram

Два независимых переключателя **Reddit news** и **Telegram news** находятся во вкладке **experiments** и изначально выключены. Списки задаются в `config.toml` каталога данных станции:

```toml
[sources.reddit]
communities = ["python", "technology"]

[sources.telegram]
channels = ["bbcrussian"]
```

Имена без `r/`, `@`, ссылок и invite-кодов, не более 20 на источник. После изменения списков перезапустите станцию; переключатели действуют без перезапуска. Для тестов задавайте отдельный `RADIO_DATA_DIR`, чтобы не менять эфир, историю и настройки основной станции.

Reddit читает только заголовки последних 25 постов через публичную Atom-ленту `/r/NAME/new/.rss`. Это временный способ: [Reddit объявил прекращение поддержки RSS 13 ноября 2026](https://support.reddithelp.com/hc/en-us/articles/54353370049684-Changelog-October-8-2026). Он не обещает замену для сторонних сообществ; переход на официальный API требует отдельного разрешённого доступа и не входит в этот эксперимент. Ошибки доступа/429 показываются в состоянии источника, без прокси, смены доменов или попыток обойти запрет.

Telegram использует [официальный публичный предпросмотр каналов](https://telegram.org/blog/privacy-discussions-web-bots#view-public-channels): `https://t.me/s/NAME`. Аккаунт, API-ключ и бот не нужны. Читается только доступная страница последних постов: без обхода входа, ограничений региона/возраста или закрытых каналов, без загрузки медиа, комментариев и полной истории. Отсутствующий предпросмотр — ошибка источника; посты без текста или даты пропускаются. HTML предпросмотра не является стабильным API: при изменении разметки адаптер может потребовать исправления. Bot API не используется для чтения истории произвольного чужого канала.

Запросы выполняются перед ближайшим выпуском, не чаще раза в 30 минут на источник, включая ошибки. Одна недоступная лента не блокирует остальные; максимум три новые новости из каждого сообщества/канала за проверку. Учитываются существующие `sources.max_age_hours`, `blocked_words` и бюджет речи. Источники не переводят и не пересказывают текст: Reddit озвучивает заголовок, Telegram — текст сообщения в исходном языке, удаляя HTML/Markdown и URL по обычным правилам дайджеста. Новых зависимостей и LLM-вызовов в адаптерах нет.

Дедупликация хранится в базе станции: ID поста, ссылка или совпадение нормализованного текста, в том числе между двумя адаптерами. Это точное совпадение текста, а не поиск похожих сюжетов; дедупликация существующего `digest.md` не меняется. Исходная ссылка и текст остаются в истории. Новости проходят существующий путь `items → packages → TTS → очередь Liquidsoap → события эфира → timeline`; выключенный источник не подготавливает и не планирует новые пакеты, уже начавшийся эфир не прерывается.

Проверка:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_public_news.py -v
```

Тест использует отдельный временный каталог, фиксированные ответы источников и MockTTS (тестовый звук вместо человеческого голоса), но реальный FFmpeg и Liquidsoap. Проверяет разбор, дату, дубли после переподключения базы, ограничения имён/хостов, переключатели, независимость ошибок, интервал запросов и неизменный импорт дайджеста. Для второго выпуска тест переводит часы музыкального сета вперёд и использует обычную команду Next, сохраняя реальные аудио и события. End-to-end проверяет получение обоих источников, `PLAYED`/`PACKAGE_COMPLETED`, ссылки и источники в истории, а также декодирование записанного WAV. Он не подтверждает доступность интернета, качество голоса или прослушивание основной станции.
