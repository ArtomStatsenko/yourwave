# Экспериментальные новости Reddit и Telegram

Два независимых переключателя **Reddit news** и **Telegram news** находятся во вкладке **experiments** и изначально выключены. Включите нужный источник, затем откройте **Settings → News sources**. Здесь два списка: сабреддиты и публичные Telegram-каналы. Введите одно имя или ссылку и нажмите **Add subreddit** или **Add channel** (либо Enter). Проверяется только новая запись; повтор не добавляется. **Remove** удаляет одну запись без сетевого запроса. Ошибки показаны возле поля и сохраняют введённый текст. Блоков отдельных постов в UI нет; ранее заданные `posts` в конфигурации сохраняются для совместимости.


Сохранённые списки хранятся в `settings.json` и применяются к следующей проверке источника без перезапуска. Прежние значения в `config.toml` остаются значениями по умолчанию:

```toml
[sources.reddit]
communities = ["python", "technology"]
posts = []  # ссылки на конкретные треды/посты

[sources.telegram]
channels = ["bbcrussian"]
posts = []  # ссылки вида https://t.me/telegram/83
```

В UI принимаются имена, `r/саб`, `@канал` и HTTPS-ссылки соответствующего сервиса; ссылки нормализуются, повторы удаляются. Каждый список вмещает до 20 записей; поле добавления принимает одно имя или ссылку до 512 символов. В `config.toml` списки `communities` и `channels` по-прежнему содержат простые имена. Изменения самого `config.toml` требуют перезапуска; сохранение из UI — нет. Для тестов задавайте отдельный `RADIO_DATA_DIR`, чтобы не менять эфир, историю и настройки основной станции.

Reddit работает без аккаунта, Client ID и API-доступа. Для сабреддитов читаются заголовки и доступный текст последних 25 постов через публичную Atom-ленту `/r/NAME/new/.rss`. Для максимум трёх новых подходящих постов за проверку дополнительно читается RSS треда: до пяти различных коротких комментариев из первых 25 записей при сортировке Reddit Top (`sort=top`). Повторы, рекламные и слишком длинные комментарии пропускаются. Порядок популярности задаёт Reddit; приложение сохраняет этот порядок среди подходящих комментариев. Это ограниченная выборка, не мнение большинства. Уже импортированные посты повторно ради комментариев не запрашиваются; дата новости остаётся датой поста.

Пост и комментарии сохраняются одним материалом и проходят редактора вместе, до разбиения озвучки. Для вручную сохранённой ссылки на тред действует та же группировка: комментарий не становится отдельной новостью. Ссылки и даты комментариев сохраняются в происхождении материала. При недоступности комментариев сохраняется исходный пост; `comments_status` в метаданных отличает `available`, `none` и `unavailable`. Содержательные аргументы и возражения допускаются в кратком эфирном пересказе как реплики отдельных участников. Сарказм, слухи, предположения и собственная оценка ведущего явно отделяются от фактов; реплика комментатора не подтверждает содержимое невидимой картинки. Непонятный без изображения пост по-прежнему пропускается. Дополнительного запроса к LLM для анализа комментариев нет.

При добавлении сабреддита проверяется RSS только новой записи; уже добавленные сабреддиты повторно не запрашиваются, повторы не добавляются.  Ошибка доступа, отсутствующая лента, лимит запросов или сетевая ошибка показаны возле поля; прежний список и введённый черновик сохраняются. Пустой список сохраняется без запросов. Это проверка доступности RSS, а не каталог или поиск сабреддитов: при отказе Reddit нельзя надёжно отличить закрытый источник от блокировки запроса. TOML проверяет только формат; доступность заданных там источников проверяется при импорте.

Это временный способ: [Reddit объявил прекращение поддержки RSS 13 ноября 2026](https://support.reddithelp.com/hc/en-us/articles/54353370049684-Changelog-October-8-2026). Если Reddit закрывает доступ, импорт сообщает ошибку без прокси, смены доменов или обхода ограничений.

При добавлении Telegram-канала сначала проверяется его публичный предпросмотр; недоступные каналы не сохраняются. Проверка не требует аккаунта, а удаление работает и без доступа к Telegram. Telegram использует [официальный публичный предпросмотр каналов](https://telegram.org/blog/privacy-discussions-web-bots#view-public-channels): `https://t.me/s/NAME`. Аккаунт, API-ключ и бот не нужны. Для отдельных постов читается публичный предпросмотр `t.me/s/CHANNEL/ID` и выбирается только указанный ID, без соседних сообщений. Ссылки на приватные посты (`t.me/c/...`), приглашения и форумные топики с дополнительным уровнем пути не поддерживаются. Для каналов читается только доступная страница последних постов: без обхода входа, ограничений региона/возраста или закрытых каналов, без загрузки медиа, комментариев и полной истории. Отсутствующий предпросмотр — ошибка источника; посты без текста или даты пропускаются. HTML предпросмотра не является стабильным API: при изменении разметки адаптер может потребовать исправления. Bot API не используется для чтения истории произвольного чужого канала.

Автоматические запросы выполняются перед ближайшим выпуском, не чаще раза в 30 минут на источник, включая ошибки. После Reddit 429 UI и импорт используют общую паузу из `Retry-After` (секунды или HTTP-дата), а без этого заголовка — 30 минут; новые HTTP-запросы в этот период не отправляются, интерфейс показывает оставшееся время до локальной попытки. Пауза хранится в `run/reddit-rss.lock` и переживает перезапуск; это не гарантия, что Reddit снимет ограничение к указанному времени. Явное сохранение изменённого списка разрешает новую проверку перед выпуском; ответ по ссылке, удалённой во время запроса, отбрасывается. Одна недоступная лента не блокирует остальные; максимум три новые новости из каждого сообщества, канала или выбранного треда за проверку. Уже собранные новости при редактировании списков не удаляются. Учитываются существующие `sources.max_age_hours`, `blocked_words` и бюджет речи: старый пост по вручную добавленной ссылке тоже не попадёт в эфир после истечения срока свежести. Адаптеры сохраняют исходные заголовки, комментарии и сообщения без перевода. Перед озвучкой общий редактор готовит краткий пересказ по-русски через выбранную в Settings модель; исходный текст сохраняется, а история показывает утверждённый текст эфира. При ошибке или отказе редактора оригинал в эфир не проходит. Действуют общие лимиты LLM-вызовов, кеш и проверки текста; в самих адаптерах обращений к модели нет.

Дедупликация хранится в базе станции: ID поста, ссылка или совпадение нормализованного текста, в том числе между двумя адаптерами. Это точное совпадение текста, а не поиск похожих сюжетов; дедупликация существующего `digest.md` не меняется. Исходная ссылка и текст остаются в истории. Новости проходят существующий путь `items → packages → TTS → очередь Liquidsoap → события эфира → timeline`; выключенный источник не подготавливает и не планирует новые пакеты, уже начавшийся эфир не прерывается.

Проверка:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p test_public_news.py -v
```

Тест использует отдельный временный каталог, фиксированные ответы источников и MockTTS (тестовый звук вместо человеческого голоса), но реальный FFmpeg и Liquidsoap. Проверяет разбор, дату, дубли после переподключения базы, ограничения имён/хостов, переключатели, независимость ошибок, интервал запросов и неизменный импорт дайджеста. Для второго выпуска тест переводит часы музыкального сета вперёд и использует обычную команду Next, сохраняя реальные аудио и события. End-to-end проверяет получение обоих источников, `PLAYED`/`PACKAGE_COMPLETED`, ссылки и источники в истории, а также декодирование записанного WAV. Он не подтверждает доступность интернета, качество голоса или прослушивание основной станции.
